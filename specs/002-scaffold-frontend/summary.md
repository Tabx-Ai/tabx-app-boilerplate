This is the front half of the app: the screen, the pieces screens are made of, and the single place it talks to its backend. It ships the usual set of interface components once, along with page furniture like headers, pagers and empty states, so that every screen built later looks the same without anyone deciding again. Exactly one file makes network calls, and every failure that comes back is turned into one kind of error, so no screen invents its own way of saying something went wrong. One file reads settings, for the same reason. Pages are added by creating a folder rather than editing a list. Two small tests hold the rules that would otherwise rot quietly: that only the one file reaches the network, and that every page renders exactly one main region, which nothing complains about when missing but a screen reader user notices at once.
