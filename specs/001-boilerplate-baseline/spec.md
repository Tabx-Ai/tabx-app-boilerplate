# Spec 001 — The boilerplate baseline

**Status:** merged
**Target:** `backend/`, `frontend/`, and the root record files.

This spec is the **worked example** every later spec copies: it records what the seed this app
started from contains, in the five-file format the constitution requires. It was implemented by
the platform (TabX spec 099) before this app existed; its eval is the template's own gate.

---

## Why

An app generated by Architect starts from a seed, and the seed's contents are design decisions
somebody made — the envelope contract, the identity seam, the two-project layout. Recording them
as a spec means the first real feature spec written in this repo has a predecessor to imitate,
and the decisions have a place a session can read instead of re-deriving them from code.

## Functional requirements

- **FR-001** `backend/` is a Hono app with **one Lambda entry point** (`src/handler.ts`) whose
  invocation payload is the request envelope `{ path, method, query, body }` plus the
  platform-injected context; an internal router dispatches to `src/services/<name>/`.
- **FR-002** An invocation **without valid context is refused** with a typed 401-shaped
  envelope (`src/context.ts` is the only reader of raw identity).
- **FR-003** **Nothing throws out of the handler**: unknown path → typed 404 envelope; a thrown
  service error → typed 500 envelope. A Lambda that throws gets retried by some invokers, which
  duplicates side effects.
- **FR-004** Config is Zod-parsed once in `src/config/`; a missing required key fails loudly
  and names the key; `.env.example` lists every key the module reads.
- **FR-005** A local dev harness (`src/dev-server.ts`) wraps plain HTTP into the envelope plus
  a fake context and feeds the same handler, so the whole chain runs without AWS.
- **FR-006** `frontend/` is a Vite + React + strict TS SPA on Tailwind v4 + shadcn/ui, with
  folder routing, TanStack Query, and React Hook Form.
- **FR-007** The client (`src/api/client.ts`) sends every call as the backend envelope through
  the platform proxy; the **pass token** is read once at boot from the URL, held in memory
  only, and attached to every call; a missing token renders the "opened outside TabX" state
  and the client refuses to fire.
- **FR-008** One sample service (`hello`) and one sample page prove the whole chain, both
  labelled throwaway in their own code.

## Success criteria

- **SC-001** Both projects install, typecheck, test and (frontend) build green from a bare copy
  of this folder, anywhere.
- **SC-002** The dev harness answers `/hello`; refuses a context-less call; 404-envelopes an
  unknown path.
- **SC-003** The committed `manifest.json` validates against `manifest.schema.json`, and a copy
  carrying an unknown key still validates.

## Non-goals

Deploy tooling, the platform proxy itself, any vendor SDK — see the constitution and
`stack.md`.
