Every generated app already gets its own empty database schema, but had no way to reach or shape it. This spec gives it both. A new migrations folder at the app repository's root holds numbered SQL files describing how its schema should change; the platform runs any new ones forward on every deploy. Inside the backend, a real database client reads a connection string and a schema name from environment variables the platform provides, so the app's code can read and write rows without naming the schema itself. Because nothing records which files have already run, every migration must be safe to run more than once. A new skill teaches whoever adds a table how to follow that rule and reach the client correctly. The constitution gains a new article describing this, and corrects an old line claiming this app owns no schema, which is no longer true.
