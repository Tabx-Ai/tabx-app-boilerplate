The backend used to put everything about a feature in one file: how a request is read, what the feature does, and where its data would come from. That works for a sample and fails the first time an app needs a database or an outside service, because there is nowhere for the code that talks to either. This spec gives the backend four homes and a rule about who may reach what: settings, features, storage clients, and outside services. Each feature is split into three files, always, so the first time it reads anything there is exactly one place that can. The shared routing file becomes a list of mounts, so adding a feature touches two lines of shared code rather than growing a file every other feature edits. Tests read the folder layout itself, because none of these rules is visible while the code runs.
